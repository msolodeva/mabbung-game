# 전략적 AI 시스템 디자인 (Strategic AI System)

## 1. 개요
현재 AI의 근시안적인 의사결정 구조를 개선하여, Gem Grab 모드의 목표를 이해하고 팀원 간의 유동적인 역할 분담을 통해 전략적인 플레이를 수행하도록 합니다.

## 2. 주요 시스템

### 2.1 전역 상황 인지 (Global Awareness)
AI가 `GemGrab` 모드의 실시간 데이터를 인지하도록 확장합니다.
- **팀 데이터 접근**: 우리 팀/상대 팀의 총 보석 수, 승리 카운트다운 상태, 남은 매치 시간.
- **고가치 타겟(HVT) 식별**: 보석을 많이 보유한 적을 실시간으로 추적하여 공격 우선순위를 상향합니다.

### 2.2 실시간 역할 할당 (Dynamic Role Assignment)
보석 보유량에 따라 팀 내 역할을 자동으로 전환합니다.
- **보석 운반자 (Carrier)**: 팀 내 보석 최다 보유자. 생존과 보석 보존에 집중합니다.
- **호위병 (Protector)**: 운반자를 제외한 나머지 팀원. 운반자 근처를 지키며 적의 접근을 차단하고 화력을 지원합니다.
- **역할 교대**: 운반자 사망 시 근처의 호위병이 즉시 새로운 운반자가 되어 전략을 수정합니다.

### 2.3 전략적 타겟팅 가중치 (Strategic Weighting)
기존 거리 기반 타겟팅 로직에 전략적 점수를 추가합니다.
- `Score = (BaseValue) - (Distance * Factor) + (StrategicBonus)`
- **StrategicBonus 항목**:
    - 적 보유 보석 1개당 `+200`
    - 적 체력 30% 이하 시 `+500`
    - 우리 팀이 패배 위기(상대 카운트다운) 시 보석 보유 적 가중치 `2배`

## 3. 행동 양식 변화

### 3.1 운반자 (Carrier) 행동
- 보석 5개 이상 보유 시 적 추적(`chase`)을 자제하고 아군 진영 또는 기지로 후퇴하는 경향을 보입니다.
- 위험 상황 발생 시 공격보다 회피 무빙에 더 높은 우선순위를 둡니다.

### 3.2 호위병 (Protector) 행동
- 적이 사거리에 없더라도 운반자 주변 3~4타일 내에 머무르며 대형을 유지합니다.
- 운반자를 공격하는 적을 최우선으로 제거합니다.

## 4. 구현 단계
1. `AIController`와 `GemGrab` 간의 데이터 브릿지 구축
2. 역할 판정 로직 추가 (`findTeamCarrier`)
3. `findBestStrategicTarget` 내 가중치 로직 업데이트
4. 역할별 이동 목표 선정 로직(`updatePositioning`) 구현
