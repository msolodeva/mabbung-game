# Street Fighters — 2D Versus

TypeScript / Canvas로 만든 로컬 2D 격투 게임입니다. 류·춘리와 네 명의 새 도전자로 구성된 6인 로스터를 지원합니다.

## 실행

```sh
npm install
npm run dev
```

화면 아래에서 CPU 대전, 2인 대전, 트레이닝을 선택합니다. 캐릭터 선택은 1P WASD, 2P 방향키, 확정은 각각 F / Enter입니다. CPU·연습 모드에서는 방향키로 상대를 고른 다음 F로 시작합니다. 선택 화면에서 F3으로 스테이지(자동 → 도장 → 네오 도쿄 → 사우스타운 → 자동), H로 CPU 난이도를 바꿉니다. 화면 하단의 스테이지·난이도 문구를 클릭해도 변경됩니다.

| 동작 | 1P | 2P |
| --- | --- | --- |
| 이동 / 점프 / 앉기 | WASD | 방향키 |
| 약공격 / 강공격 | F / G (J / K) | I / O |
| 필살기 / 초필살기 | H / R (L / U) | P / [ |
| 가드 | 뒤로 유지 또는 Space | 뒤로 유지 또는 Enter |
| 잡기 | F + G | I + O |

↓↘→ + 공격은 장풍, →↓↘ + 공격은 대공기, ↓↙← + 공격은 회전 공격입니다. ↑ + 필살기 / ↓ + 필살기로도 대공기 / 회전 공격을 사용할 수 있습니다. 초필살기는 게이지 한 칸을 사용합니다. 약공격이 적중한 경우에만 허용된 후속 기술로 캔슬할 수 있습니다.

게임패드는 방향키·스틱 이동, A/X 약공격, B/Y 강공격, RB 필살기, RT 초필살기, LB 가드를 사용합니다. 두 패드는 각 플레이어에 대응합니다.

Esc 일시정지, F1 도움말, F2 판정 표시. 트레이닝에서는 F4 초기화, F6 더미 행동 변경, F7 정지, F8 한 프레임 진행을 지원합니다. 창에서 포커스가 벗어나면 자동으로 일시정지됩니다.

## 연속 공격 대응

- 막힌 기본기는 필살기로 캔슬할 수 없어 공격 후 반격할 틈이 생깁니다.
- 일반 장풍은 플레이어마다 화면에 한 발만 유지할 수 있고, 발사 후 회복이 8프레임 늘었습니다.
- 점프 높이와 체공 시간을 늘려 장풍을 넘으며 전진하기 쉽게 했습니다. 달심은 다른 캐릭터보다 낮은 점프를 유지합니다.
- 일반 장풍을 막으면 체력이 줄지 않고 가드 소모·밀림·경직이 줄어듭니다. 막은 뒤 전진하거나 점프로 접근하세요. 초필살기 장풍은 기존 방어 피해를 유지합니다.

## 개선 내용

- 류·춘리 각각 32개 포즈의 투명 스프라이트, 대기·걷기·킥 동작과 피격·가드·다운·승리 표현
- 석양 도장 배경, 새 타이틀·캐릭터 선택·체력·게이지·초필살기 연출
- 렌더링 주사율과 분리된 고정 60Hz 시뮬레이션
- 기술별 발동·지속·회복 시간, 상하단 방어, 잡기와 동시 잡기 풀기, 카운터, 콤보 보정, 적중 캔슬
- 양측 접촉을 먼저 수집해 동시타를 처리하는 판정, 장풍 상쇄와 중복 적중 방지
- 입력 버퍼, 짧은 키 입력 보존, 패드 버튼 최초 입력 감지
- 연습 더미, 입력 이력, 기술 단계와 프레임 진행, 판정 시각화

## 캐릭터 구성

류·춘리는 기존 스프라이트와 전투 설정을 유지합니다. 이전의 테리·이오리·가일·마이는 제거했습니다.

| 캐릭터 | 전투 스타일 | H 필살기 | ↓ + H |
| --- | --- | --- | --- |
| 캐미 | 빠른 이동과 근접 압박 | 스파이럴 애로: 하단 돌진 | 훌리건 킥 |
| 장기에프 | 느린 이동, 강한 기본기와 잡기 | 스크류 파일드라이버: 근접 가드 관통 | 더블 래리어트 |
| 달심 | 긴 기본기로 거리 유지 | 요가 파이어: 장풍 | 요가 플레임: 제자리 화염 |
| 블랑카 | 전기 연속타와 빠른 롤링 | 일렉트릭 썬더: 근접 다단 공격 | 롤링 어택 |

새 캐릭터는 각각 16개 포즈의 스프라이트를 사용합니다. ↑ + H는 대공기, R은 게이지 한 칸을 사용하는 초필살기입니다. 장기에프의 초필살기도 잡기이므로 가까이에서 사용해야 합니다. 기술은 이 데모의 공통 입력 체계에 맞춰 구성했으며 원작의 기술 판정과 프레임을 그대로 재현하지는 않습니다.

이미지 자산은 이 프로젝트를 위해 생성했으며 공식 게임에서 추출한 스프라이트가 아닙니다. 생성 프롬프트와 자산 경로는 [자산 제작 기록](public/assets/GENERATED.md)에 기록합니다.


## 시각·음향 연출

- 약공격·강공격·가드·가드 붕괴·KO에 맞춘 타격 섬광과 확장 충격파
- 시뮬레이션 프레임 기준으로 감쇠하는 카메라 흔들림과 짧은 확대
- 돌진·대공·회전 공격의 포즈 잔상, 부드러운 착지 먼지, 캐릭터 색상에 맞춘 장풍 코어와 궤적
- 초필살기 초상 컷인, 진행하는 속도선, 발동 중 배경음 감소
- 저음·타격 노이즈·공기음을 겹친 효과음, 캐릭터별 필살기 음색, 공격 위치에 따른 좌우 패닝

화면 아래 **연출 강하게 / 연출 부드럽게** 버튼으로 흔들림·잔상·화면 가장자리 효과·컷인 이동을 줄일 수 있습니다. OS의 동작 줄이기 설정을 초기값으로 반영합니다. 효과음과 BGM은 각각 켜고 끌 수 있습니다. 연출 변경은 공격 프레임·데미지·입력 판정에 영향을 주지 않습니다.

## CPU 대전과 스테이지

기본 난이도는 **NORMAL**입니다. EASY / NORMAL / HARD는 최소 관찰 지연(20 / 12 / 8프레임), 판단 주기, 공격 사이의 여유, 가드·대공·접촉 캔슬 성공 확률이 다릅니다. 상대의 버튼이나 입력 버퍼를 읽지 않으며, 뒤로 날아가는 장풍은 방어 대상으로 취급하지 않습니다. 히트스톱 동안 판단 시계도 멈추고 매 라운드 판단 이력을 초기화합니다.

류는 장풍과 기본기, 춘리는 빠른 기본기와 연속 킥, 캐미는 접근과 돌진, 장기에프는 잡기 거리 진입, 달심은 긴 기본기와 원거리 장풍, 블랑카는 근접 전기와 롤링을 중심으로 선택합니다. 기술마다 실제 사거리·이동 거리·게이지·공중 여부를 확인합니다.

스테이지 **AUTO**는 상대 캐릭터에 맞는 테마를 선택합니다. 수동 선택은 상대를 바꿔도 유지됩니다.

| 스테이지 | 자동 배정 상대 | 배경·사운드 |
| --- | --- | --- |
| 주작성 도장 | 류, 달심 | 기존 석양 도장, 바람·종소리와 100 BPM 오음계 선율 |
| 네오 도쿄 | 춘리, 캐미 | 비·네온·움직이는 전철, 빗소리와 124 BPM 신스 비트 |
| 사우스타운 | 장기에프, 블랑카 | 해안·현수교·차량 불빛, 도로 소음과 112 BPM 베이스·드럼 |

음악은 이 프로젝트용 합성 선율이며 원작 곡을 사용하지 않습니다. 첫 사용자 조작 후 BGM이 재생되고, BGM 버튼은 음악과 환경음을 함께 켜고 끕니다. 효과음은 별도로 제어합니다. 일시정지·도움말에서는 배경음 볼륨이 낮아집니다.

`node scripts/audit-cpu.mjs`는 6×6 캐릭터 조합을 3개 난이도로 최대 60초씩 시뮬레이션하고 `output/cpu-audit.json`에 체력·기술 사용·진행 시간을 저장합니다. 고정 난수 시드의 동작 점검용이며, 사람 상대의 승률이나 완전한 캐릭터 밸런스를 보장하는 결과는 아닙니다.

## 검증

```sh
npm test
npm run build
```

`tests/combat.test.ts`는 주사율 독립성, 동시타, 방어, 잡기, 무적, 장풍, 캔슬, 착지, 구석 충돌, 입력을 검증하며, 새 캐릭터의 돌진·잡기·사거리·전기 연속타 및 필살기 종료도 확인합니다. `tests/browser-smoke.js`는 개발 서버에서 Playwright CLI의 `run-code`로 실행하는 브라우저 시나리오입니다. 초필살기, 한 프레임 진행, 일시정지, 기본기, KO, 결과 화면, 작은 화면 레이아웃을 확인하고 `output/playwright/`에 스크린샷을 남깁니다. `tests/browser-roster.js`는 6명 × 16개 포즈의 로딩·렌더링과 신규 4명의 선택, 필살기 적중, 초필살기 발동을 검증합니다. `tests/browser-effects.js`는 타격·컷인·잔상과 연출 강도 전환, Web Audio 출력·음소거·재생 노드 정리를 확인합니다. `tests/ai.test.ts`는 반응 지연·입력 비참조·캐릭터 전술·장풍 방향을 확인합니다. `tests/browser-cpu.js`는 6명 CPU의 실제 적중, 자동·수동 스테이지, 난이도, 스테이지별 BGM 출력과 음소거를 검증합니다. 테스트용 게임 상태 접근은 개발 모드에서만 제공됩니다.

주요 구현은 `src/combat/`(기술·접촉 판정), `src/entities/ArcadeFighter.ts`(전투 상태), `src/render/`(스프라이트·배경), `src/engine/Game.ts`(대전 흐름)에 있습니다.
